# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Atlantis**, a Z80 assembly game for the 48K ZX Spectrum (sjasmplus 1.24+). It sits on top of a small engine whose earlier parallax demo is frozen as **Engine Demo 1** (git tag `engine-demo-1`, entry `src/main.asm`, tape `build/diver.tap`).

- `src/*.asm` is shared by both programs. `src/atlantis/*.asm` is Atlantis only.
- **Trigon**, the second game (`docs/TRIGON.md`), is the Atlantis game assembled again with `TRIGON` defined: `src/trigon/main.asm` defines it, includes `src/atlantis/main.asm`, and writes `build/trigon.*`. Trigon's differences sit under `IFDEF TRIGON` (or `CODE_GATE`, the menu's code: Trigon but not its soak) in the shared files, or in `src/trigon/` (`config.asm` replaces Atlantis's whole; `theme.asm`, the fish's and missile's colours painted each step through `fish_draw_call`/`FISH_DRAW_TO`; `gate.asm`, the code). Erin's art (`gfx/trigon/`) is generated under the Atlantis names, so it drops into the same buffers. **Every change must leave Atlantis's bytes unchanged**: compare `build/atlantis.sna` and `.tap` and the test builds before and after. A DEFINE's name is substituted inside identifiers (`TRIGON` in `TRIGON_CODE` broke it; `-DCFG_SEA=0` would break `CFG_SEA_BRIGHT`), so name things to avoid that.
- **The Engine Demo 1 tape must stay byte-identical.** Do not change the bytes the demo assembles from shared files. Atlantis-only additions to a shared file go under `IFDEF ATLANTIS` (main.asm defines it). If not, they go in an Atlantis-only file, the way `src/atlantis/fastsprite.asm` replaces the shared sprite walker and `src/atlantis/scroll.asm` copies the demo's `blit_rows`.

## Build and run

```
make              # build/atlantis.tap + .sna + build/atlantis.lst/.sym
make run          # launch in Fuse (EMU=fuse-sdl by default; EMU=fuse for GTK; EMU="fuse -g 3x" to scale)
make demo         # Engine Demo 1 -> build/diver.tap
make timing       # build/atlantis-timing.sna: border colour bands show where frame time goes
make soak         # build/atlantis-soak.sna: scripted 1024-frame self-check (see below)
make trigon       # build/trigon.tap + .sna (make builds both games); make run-trigon
make trigon-seas  # build/trigon-sea-black.sna and -dark.sna (CFG_SEA)
make trigon-soak  # build/trigon-soak.sna; make unpack-check-trigon
make shot         # headless screenshot (xvfb, xdotool, imagemagick)
make input-test   # headless key/Kempston test, DEMO only (reads its row-22 digits)
make sprite-test  # headless sprite test, DEMO only
```

The usual full cycle on this machine (Fuse here is the GTK build, called `fuse`):

```
make -B && make soak && make run EMU="fuse -g 3x"
```

`make web` (or `build.bat web`, Atlantis only) copies `build/atlantis.sna` and `.tap` into `docs/play/`, and Trigon's into `docs/play/trigon/`, the GitHub Pages version (JSSpeccy 3, `docs/WEB.md`), and stamps their hashes into `docs/play/index.html`'s addresses (`tools/webstamp.sh`/`.ps1`) so browsers fetch a new build at once; commit all three. Those two copies are committed on purpose; `build/` is not.

`-B` forces a full rebuild, which also regenerates `gfx/*.asm` (needs Python 3). `make soak` only assembles `build/atlantis-soak.sna`. To see its result, run it with `fuse -g 3x --machine 48 build/atlantis-soak.sna`.

Windows: `build.bat` / `build.bat run` / `build.bat demo`.

The tapes (`build/atlantis.tap`, `build/diver.tap`) are **not tracked** any more: `make` builds them, and `.gitignore` ignores them. `build/*.png` is still committed. To check that Engine Demo 1 is unchanged, compare a fresh `make demo` with the last committed copy: `git show fc5fe34^:build/diver.tap | cmp - build/diver.tap`. `SAVETAP` paths are relative to the cwd.

Graphics: the fish, the pulsar and the spinning wheel are the exception: `tools/gfx2raw.py` writes their art unshifted (`gfx/fish_raw.asm`, `gfx/wheel_raw.asm`, and every fourth frame of `gfx/wheel-full.txt` in `gfx/wheel_spin.asm`), and `preshift.asm` makes gfx2asm.py's bytes and tables from it at start-up. The fish's and the diver's Atlantis art is `gfx/fish-atlantis.txt` and `gfx/diver-atlantis.txt` (a piranha, and new legs). The tape build (`TWO_FISH`: no stat line, not the soak) also has the round fish, from `gfx/fish.txt` via `gfx/rfish_raw.asm`, its pictures at `RFISH_BUF` (`$B5C0`); `fish_kind_pick` (boom.asm) makes one fish in four a piranha when a fish appears, patching the draw's table, and a piranha scores twice the level's fish points; Engine Demo 1 still uses `gfx/fish.txt` and `gfx/diver.txt`, through `gfx/fish.asm` and `gfx/diver.asm`, and they must not change. Otherwise `gfx/*.txt` (ASCII art: `#` ink, `-` paper, `.` transparent; `mirror off` skips the left-facing copy) is turned into `gfx/*.asm` by `tools/gfx2asm.py`. The generated `.asm` files are committed so Windows builds don't need Python. `make` regenerates them when the `.txt` changes. The tape's loading screen, `gfx/loading.scr` (6912 bytes, committed), is drawn from the same art by `tools/mkloadscreen.py`, which paints at full colour, cuts each 8x8 cell to two colours, and prints any cell that clashed. It also prints the version from `VERSION` (one line, e.g. `0.9.0`) small on the sand in the bottom right corner: for a release, change `VERSION`, run `make` (Python 3 redraws the screen; commit `gfx/loading.scr`), then `make web`.

## Testing: there is no unit-test framework

Verification means assembling a variant build with `-D` flags and running it in Fuse. Each variant writes its own `.sna` (see the bottom of `src/atlantis/main.asm`), and the tape is only written when none of these flags is set:

| Flag | What it does |
|------|--------------|
| `-DSOAK` | `src/atlantis/soak.asm` plays a scripted dive and checks background restore, colours and the terrain clamp after every frame. **Green border + "OK"** = pass. Red border + reason number + frame = first failure (reasons are listed in soak.asm's header). It takes about 2 minutes at 50 and 3 at 25. |
| `-DTIMING_BARS` | Border colour per phase. The legend is in main.asm's header. |
| `-DMEASURE` | Runs warmup + 512 steps, then halts and prints hex on row 2: min spare scanlines, late-step count, max spare, interrupts. Row 3 is the same for the 25 fps idle frame (ending in loops). Options: `-DMEAS_DOWN` (hold Down, the heavy seabed case), `-DMEAS_FIRE` (tap fire every other step, so a torpedo is nearly always running), `MEAS_RATE`, `MEAS_WARMUP`, `MEAS_WINDOW`. Judge the speed by interrupts: 1 per step at 50, 2 at 25. At 50 the heavy case shows a handful of late steps that overrun by a few T-states and catch up; that count moves by 1-2 with schedule alignment alone. |
| `-DSLACK_LINES=n` | Adds an n-scanline NOP sled. Green/red border shows whether the frame still fits. Optional `SLACK_WARMUP`. |
| `-DSHOT_FRAME=n` | Halts after loop n for a deterministic screenshot. |
| `-DNO_WHEEL` | Leaves the wheel bomb out, for measurement. |
| `-DMEAS_BOOM` | With `-DMEASURE`: an explosion over the diver all the time (a new one as soon as the last ends), with its sound. The worst case for the explosion's cost. |
| `-DMEAS_SPIN` | With `-DMEASURE`: every bomb is the spinning wheel (level 3's bomb), whose pictures are read from contended RAM at `$78E0`. Compare with the same build without it. |
| `-DNO_STATS` / `-DSTATS` | The stat line (`stats.asm`, Symbol Shift + S) is in every test build above and left out of the tape. `-DNO_STATS` takes it out of a test build (to compare it with the tape's code); `-DSTATS` puts it in the tape. |
| `-DMEAS_MISSILE` | With `-DMEASURE`: a silo missile armed or flying all the time (no gap). A missile that reaches the measuring diver passes through him. |
| `-DMEAS_LEVEL=n` | With `-DMEASURE`: the game starts at level n (as its code would), so a later level's movers and colours can be measured. `-DMEAS_LEVEL=2` is level 2's wave bomb and wave fish. |
| `-DNO_SOUND` | Leaves the beeper out of any build, so timing can be compared with and without sound. |

Example: `sjasmplus --nologo --fullpath=off -DMEASURE -DMEAS_DOWN src/atlantis/main.asm`, then `fuse-sdl --machine 48 build/atlantis-measure.sna`.

After a change that touches the frame loop, sprites, scroll, stats or input, run the soak and check spare scanlines in the heavy case (diver on the seabed, wheel on screen). Commit messages here report those numbers.

## Architecture

**The frame budget is the main constraint.** The heavy seabed frame has only a couple of scanlines to spare at 50 fps, so a new instruction in the per-frame path can make the frame miss the interrupt. Comments throughout record T-state counts and measured spare lines. Keep those numbers up to date, and prefer unrolled code in hot paths, as the existing code does.

**Main loop order** (`src/atlantis/main.asm`, `main_loop`). The order follows the raster beam:
1. `chords_poll` (Symbol Shift + P/F/S, edge-triggered via `rising_edge`), then `read_input`, which gives one `000FUDLR` byte in `input_state`
2. Restore sprites in **reverse** draw order: diver, wheel, fish
3. `stats_prepare`. Draw sprites that are still above the seabed (row 21) *before* the seabed copy
4. `scroll_blit` copies the off-screen buffers to rows 21-23 and stamps the silo towers and domes. `draw_late` then draws the sprites that overlap the seabed, so they photograph this frame's ground
5. Rotate the ground buffer (1px per 1/50 s) and the slow sand/weed buffer (every other 1/50 s, tracked by `slow_phase`)
6. Stats overlay (test builds only), then `update_diver` / `update_fish` / `update_wheel`
7. `spare_count` (`src/atlantis/rate.asm`) busy-waits in an exact 224-T-state loop until the interrupt. **This wait is the vsync**, and it also measures spare scanlines

**50/25 fps**: every speed is written per 1/50 s. `step_ticks` is 1 or 2. At 25 each step is two television frames: the picture frame only restores, draws and copies the seabed, and `idle_tick` (the next frame) shifts the ground twice and the slow buffer once, then runs the movement twice on the one-pixel paths. `rate_apply` patches the two jumps in `main_loop` (`step_jp_shift`, `step_jp_move`) that skip the shifts and the moves on the picture frame. The wheel applies `step_ticks` internally, so don't call it twice.

**Missiles** (`missile.asm`): one at a time, armed after a random gap in a silo on screen whose missile will leave within `CFG_MISSILE_RANGE` of the diver (`msl_near`), then straight up. It leaves only at a ground shift that puts it in one byte, so in flight it is one byte a row. Up in the water it is the first sprite drawn after the explosion and the last restored; in the hatch it is the first late sprite. `msl_vn` records which, like `torp_vn`.

**Score and row 1** (`score.asm`): each new level tops the lives up to `CFG_LEVEL_LIVES` in `level_up` (cold), which only a real level change calls (a level code's start uses `level_advance`). BCD score (3 bytes, low first), levels from `CFG_LEVELS` (target, missile gap, bomb haste, bomb kind: the pulsar or, from level 3, the spinning wheel, switched per bomb by `wheel_type`; then how the level looks: bomb ink, bomb movement, hunt, fish movement, fish haste, border; then what a shot scores: fish, bomb, missile; level 1 must stay the old game). The level codes depend only on the level number, so the table can change without changing a code. Don't put codes or point targets in `docs/` (it's the public web site): they live in `notes/LEVEL-CODES-LIST.md`. The look is applied by `level_style` (`level.asm`): level 2's wave bomb (`wheel_wave`, kind 1) and wave fish (`fish_wave`, patched into `fish_mv`/`fish_mv2` through `fish_mover`) are hot code; a wave fish writes its height into the three hit tests' `FISH_SWIM_Y` operands (`fish_touch_y`, `fish_aside_y`, `torpedo_fish_y`). From level 4 the bomb is the hunter (`wheel_home`, kind 2, `MOVE_HOME`): the bob, with its middle drifting a pixel towards the diver's depth each time the level's `hunt` (1-128, asserted) carries, until it has passed him. The spinning wheel's spin hold is patched per bomb by `wheel_type` (4 or 3 1/50 s, from the haste, so it rolls); the pulsar keeps `WHEEL_SPIN`. A fixed border is written over the heartbeat's first four bytes (`step_skip.beat`). The bomb's top never goes above `WHEEL_TOP_Y` (16, below the score line), except in the soak, whose script needs the old surface bomb on row 0. Level codes: `codes.asm`, high score. Row 1 holds the score line and the hearts. It is drawn by `hud_draw` straight after the restores, when no sprite is on screen, and only when a bit of `hud_dirty` is set, so sprites photograph it like water. Row 0 stays the debug line's. The "LEVEL n" banner is attribute cells only (rows 7-11), so no sprite photograph is involved.

**The UDG area** (`$FF48-$FFFF`, `udg.asm`: the ROM's UDGs and 16 bytes below): the title's 8x16 letters (`title_draw`, menu.asm), the four seaweed plants, the rock, and row 1's cells in kind order (`udg_water`, the heart, the bubble, the suction, shove and nuke bombs: kind n's cell is `udg_water + 8n`, drawn by `lives_draw`/`hud_cell`; `power_build` makes the sinking power-ups' masked pictures from them at start-up, at `POWER_PICS`, after the slope tables). Its own tape block: the packed tape unpacks it last, from the second block; the plain tape's BASIC loads it as a fourth block. Asserted clear of the IM2 table and the stack. **The seabed's tops** curve (smoothstep, `slope_curve`) from each column's height to the next's, so peaks and dips are rounded: `slope_build` (start-up) fills `SLOPE_GROUND`/`SLOPE_SAND` at `$FB80`, and new columns copy from there (`slope_copy`). The seaweed is picked per plant (`weed_seed`).

**Power-ups** (`POWERUPS`: not the soak, not a measurement; each kind's first level and share of the roll are pairs in `power_tab`, then the piranha's level, which a testers' switch on the menu (`cheat_poll`, cold block) sets to 1: see notes/CHEATS.md, and keep it out of `docs/` and the README): the missile's slot (`msl_kind`) sometimes holds a heart (a life, up to `CFG_LIVES_MAX`), a bubble (the double shot for `CFG_DOUBLE_TIME`) or a special bomb (`special.asm`: suction, shove, and the nuke, a testing knob that `CFG_NUKE_LEVEL` 0 leaves out; keep the nuke out of `docs/` and the README), rolled in `missile_gone`, sinking byte-aligned from `POWER_TOP`, taken by touch in `missile_hit`. The double shot (`DOUBLE_SHOT`; `-DMEAS_DOUBLE` measures it) lets a second torpedo be out (the gun's cooldown is `CFG_DOUBLE_COOLDOWN` then, as `CFG_FIRE_COOLDOWN` outlasts most crossings): firing while one runs hands it to the `t2_*` block (`T2_OFF` on, same layout, asserted); `t2_draw`/`t2_restore` are the torpedo macros at that offset, and its move and hit run the first's routines through `t2_swap`. While a second exists `torp_two_set` patches main_loop's seven torpedo calls (`.torp_rc1-3`, `.torp_dc1-2`, `.torp_hc1-2`, opcodes and operands asserted) to the "both" routines, so a single torpedo costs nothing. Its clock is `double_tick`, patched into main_loop's two `missile_update` calls (`.msl_uc1-2`) only while it lasts (`msl_calls_set`, special.asm, is the only writer of those calls: `sp_tick` while a special bomb moves things, then `double_tick`, then `missile_update`); `double_end` takes its bubble off row 1 (drawn by `lives_draw`) and plays `snd_tune_down`. A label inside `main_loop` (even `equ`) starts a new local-label scope: keep new labels out of it. A special bomb is carried (`sp_held`, drawn on row 1 four cells left of the hearts) and set off with B: while one is held, main_loop's `call chords_poll` (`main_loop.chord_call`) is patched to `sp_poll`, so nothing reads the key otherwise. Suction and shove run for `CFG_SPECIAL_TIME` through `sp_tick`, moving the bomb's middle (`wheel_base`) or x with `wheel_odd` set, and the fish's middle (the operand of `fish_wave.in`, put back by `level_style` and each new fish) or x. Setting one off patches the heartbeat's flash colour (`step_skip.flash_ink`, put back to white by the chords under `POWERUPS`), flashes for `CFG_SPECIAL_FLASH` steps and plays its slide (`snd_tune_suction`/`snd_tune_shove`); the nuke keeps the whoosh. Shove and the nuke first run `sp_quake` (cold, blocking like the knell): `CFG_QUAKE_TIME` of the whole picture copied `CFG_QUAKE_SHAKE` rows down and back through `ROW_TABLE` (exact but for the bottom rows, the ground's, which the next seabed copy rewrites), the border flashing, a fading random rumble, then `banner_until`/`double_until` pushed on by the time taken. Suction is the escape and kills nothing. A shove's enemies blow up and score as a torpedo kill when they reach the right edge (`sp_bomb_down`, `sp_fish_kill`, cold), or at the end (`sp_end`); shove blows up the missile at once, in `special_fire`, and suction takes it away silently. One burst at a time: the bomb waits for a burst to end, the fish flashes while one is up or the bomb is there; `fish_set_y` writes a straight fish's height and its three hit tests. The round fish's pictures are split: the right-facing pair at `RFISH_HI` (just below `BSS_LIMIT`), the left-facing at `RFISH_BUF` (below the jet's). **The packed tape** (`tape.asm`): the first block is the packed loading screen, then the unpacker, ending at `$8000`; the second holds the packed code, cold block, data and UDG block, unpacked in that order, each over bytes already read, and loads as high as it goes, ending at `$FF48` (`PACKED_ORG`). So `cold_end` may grow to `$78E0` (the unpacker's code is asserted above it), and the second block's room is from `code_end` (asserted below its start) to `$FF48`; its data's packed bytes must stay above `data_end` (asserted). `tape.asm` DISPLAYs the room left. `make unpack-check` proves a change to it: its sums must match `build/*.bin`.

**Hits and sound**: a bomb, a fish, a missile, or sinking onto the black (`clamp_to_terrain` sets `diver_touch` under `IFDEF ATLANTIS`) all go through `diver_hurt`, which returns carry: the step stops there and the death starts (`death.asm`, cold block). The death freezes the game by pointing `step_jp_shift` at `step_skip` and `step_jp_move` at `death_step`, with `step_ticks` 1 at either speed (`rate_apply` re-freezes if the speed is changed meanwhile). The diver flashes for `CFG_DEATH_FLASH`, then `diver_draw_fast` is patched to `diver_draw_none` and a burst goes off where he was. After `CFG_DEATH_TIME` the life is taken and the speed's jumps are restored, or the game goes to `game_over`. The banner's clock is stopped meanwhile. A MEASURE build only clears `diver_touch`, so `MEAS_DOWN` can sit on the seabed. The explosion is the bottom layer: `boom_hook` (the `call stats_prepare` after the restores) is patched to `boom_step` while one is up. Sound (`sound.asm`) plays only inside `spare_count`'s wait for the interrupt, one scanline per pass, so it cannot make a frame late; at 25 only the idle frame's wait plays it (`snd_gate`). Each sound is a six-byte `SND_DEF` (bursts, length, density, pitch); a new one replaces the last. A tune (`snd_tune_start`, the level jingle) swaps the 7-byte noise step in `snd_tick` for an equal-time tone step (`snd_op_tone`). The torpedo's laser (`snd_laser_start`, notes in `CFG_LASER`) is a tune too. It starts on the step that fires, but only into silence, and a later explosion cuts it short. The game-over knell (`snd_knell`) is the one blocking sound.

**Sprites**: masked, pre-shifted copies (8 shifts per frame), so drawing involves no run-time bit shifting. The diver's jet is animated by `diver_jet_build` (preshift.asm), which adds its two phases to the art at start-up (not to `gfx/diver.txt`, which Engine Demo 1 shares) and builds two more still pictures (`JET_BUF`, just below `$C400`; not in the soak, whose code is there). `diver_image_index` (under `IFDEF DIVER_JET`) shows them every other 4 frames while he is still; the kick only runs while he moves. Each sprite has a background record (`BG_*` offsets in `src/sprite.asm`) addressed through IY. Save, draw, then restore next frame. `fastsprite.asm` is Atlantis's faster walker, which also clips at the left and right edges. The ISR only preserves AF and HL, and the fast walker relies on that.

**Memory map** (`src/constants.asm`, `src/atlantis/layout.asm`; enforced by `ASSERT`s at the end of main.asm):
- `$6000` the **cold block**, up to `cold_end` (at most `$78E0`): code and words that only run on the menu, at start-up or once in a while (the loading screen's pause before the menu, `screen_pause`, `CFG_SCREEN_PAUSE`; the story, `story.asm`, typed when the menu's 1 starts a game, before `game_reset`; a level code goes straight in; only where boot goes to the menu: `TYPEWRITER`, defined in main.asm; the attract demo's menu side, `demo.asm` under `AUTOPLAY` (defined with `TYPEWRITER`): after `CFG_DEMO_WAIT` idle seconds `demo_idle` patches main_loop's `call read_input` (`main_loop.input_call`) to `demo_input` (hot: aims level with the bomb or fish ahead, fires, dodges missiles; a key or `CFG_DEMO_TIME` jumps to `enter_menu`, whose `demo_off` puts `read_input` back) and starts level 1; `game_over` in a demo goes straight to the menu, so no knell and no high score; the city interlude (`interlude.asm` under `CITY_SHOW`, defined with `TYPEWRITER`, in the hot code as the cold block is full): `level_up` calls it on reaching `CFG_INTERLUDE_LEVEL` + 1, `il_show` blacks the screen, unpacks `city_pix_zx0` straight to it and `city_atr_zx0` to `IL_ATTRS` (free room at `data_end`; both from `gfx/city.scr` via `tools/mkcity.py`, all committed), then `il_circle` copies the colours in a growing circle with a `CFG_INTERLUDE_RIM` ring; then `il_ending` (black, the Trigon code from `GATE_WORD` in codes.asm, until a fresh key), `score_game_over`, and `enter_menu`: Atlantis ends at the city; a testers' jump and a menu code that shows just the picture (`il_menu_code`, called by `menu_code`) are in notes/CHEATS.md; menu, level codes, `preshift` and the raw art it reads, resets, the level 2 message, `text.asm`, and routines that run once per event: the level-up chain and `banner_show`, `wheel_type`, `missile_gone`). Packed in the tape's second block (the BASIC is `CLEAR 24575`). Contended RAM, so **nothing that runs every frame may go there**. A routine is moved by putting `COLD` before it and `HOT` after it (main.asm), at routine boundaries. The soak build's own code follows it.
- `$78E0-$7FFF` the spinning wheel's shifted pictures (4, quarter turns), built at start-up by `preshift` from `gfx/wheel_spin.asm` (contended, but measured to cost nothing at 50; see `docs/WHEEL-BOMB.md`)
- `$8000` code, up to `code_end`, which must be ≤ `RFISH_BUF` (`$BCE0`, the round fish's left-facing pictures, tape build) and `JET_BUF` (the diver's two still jet pictures, 960 bytes just below `DATA_START`, `$C400`, built at start-up). Tables that are only read go in the data block, not here. The soak build's photographs and code follow it instead (it has no jet pictures).
- `$C400` data: graphics, tables (with the round fish's and the double shot's) and `data.asm`, up to `data_end`, which must be ≤ `PRESHIFT_START` (`$DA70`, the diver's shifted copies: even shifts only, as `diver_draw_fast` draws him at even x; `PRESHIFT_EVEN`, and `preshift` skips odd shifts for a job whose last byte is 1)
- `$E5B0-$EFFF` the fish's and the pulsar's shifted pictures, built at start-up by `preshift` (`preshift.asm`) from `gfx/fish_raw.asm` and `gfx/wheel_raw.asm`
- `$F300` the buffers that start empty (`bss.asm`, one list for the whole game; a new `ds` buffer goes there, not in its file), zeroed by `boot`, not on the tape
- `$F000` scroll buffers. These are built at run time and must be page-aligned, because the rotate uses `DEC L`
- `$FA00` pixel-row address table (built at start-up)
- the stack grows down from `$FDFC`; `$FDFD` holds `JP isr`; `$FE00` is the 257-byte IM2 vector table of `$FD`

The ROM font at `$3D00` is read directly, and no ROM routines are called.

**Tuning knobs** are in `src/atlantis/config.asm`. That file is numbers only. Several values are pinned by `ASSERT`s, because the soak's frame numbers depend on them.

**Seabed layout**: row 21 is weed and row 22 is sand (together the slow 16px buffer); row 23 is ground (the fast 8px buffer). A silo is two tile columns (`TILE_SILO`, `TILE_SILO_R`), 16 wide and 24 tall: its base lives in the ground buffer, and its tower (row 22) and dome (row 21) are drawn every frame by code that `src/atlantis/silo.asm` builds at assembly time from the art there, one straight run per shift. The dome's cells are painted the weed's green (`silo_cells` in scroll.asm), so nothing clashes. On the frame that does not copy the weed, the domes are wiped by copying their bytes back from the slow buffer (`silo_unstamp`). The diver is clamped one pixel above the black ground (`clamp_to_terrain` in `src/diver.asm`).

## Style

The comments are plain, short English sentences that explain *why*, with cycle counts where timing matters. Each routine's header lists its inputs, outputs and the registers it corrupts (`Corrupts: AF, BC, ...`). Keep that convention. Commit subjects are one plain sentence ending in a period.
